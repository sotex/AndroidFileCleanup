# Git Commit Message 规则

## 核心要求

- **所有 commit message 必须使用中文**
- 禁止使用英文或其他语言编写 commit message
- 消息必须清晰、简洁，能够准确描述变更内容

## 格式规范

### 基本格式

```
<类型>: <简短描述>

<详细描述>
```

### 类型说明

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 bug |
| `docs` | 文档更新 |
| `style` | 代码格式调整（不影响功能） |
| `refactor` | 代码重构 |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖更新 |
| `revert` | 回退提交 |

### 示例

**正确示例：**

```
feat: 添加文件扫描进度显示

- 在主界面添加扫描进度条
- 显示当前扫描的文件路径
- 更新扫描状态文字
```

```
fix: 修复 SD 卡扫描失败的问题

修复了当 SD 卡未挂载时扫描崩溃的 bug，添加了前置检查。
```

```
docs: 更新中文 README
```

**错误示例：**

```
fix bug
```
> ❌ 缺少类型前缀，描述过于简短

```
feat: add new feature
```
> ❌ 使用了英文，必须使用中文

## 提交规范

1. **一次提交只做一件事**：避免将多个不相关的变更放在同一个 commit 中
2. **描述要具体**：说明变更做了什么，而不是做了哪些文件
3. **时态**：使用现在时（添加、修复、更新），避免使用过去时
4. **长度限制**：第一行尽量不超过 50 个字符，详细描述每行不超过 72 个字符
